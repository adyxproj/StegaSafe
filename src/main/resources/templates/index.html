Steganography & Architecture Guide

1. Steganography vs. Cryptography

Cryptography scrambles a message so that eavesdroppers cannot read it, but the ciphertext itself is conspicuous and signals that a secret exists. Steganography hides the very existence of the communication by embedding secret bits inside innocent media. StegaSafe unifies both techniques: the message is first encrypted using authenticated AES-256-GCM, and then invisibly woven into digital pixel channels.

2. How Least Significant Bit (LSB) Encoding Works

In standard 24-bit TrueColor images, each pixel consists of 3 bytes representing Red, Green, and Blue channels (0 to 255). The least significant bit (LSB) of each 8-bit color component has a weight of only 1/256. Modifying this bit produces a color shift of ±1, which is completely imperceptible to the human eye.

3. Why PNG is Strictly Required for Export

JPEG utilizes lossy Discrete Cosine Transform (DCT) compression and chroma subsampling, which completely recalculates and destroys high-frequency details (including least significant bits). PNG, in contrast, utilizes lossless DEFLATE compression, which guarantees 100% bit-exact preservation of pixel values across saves, transfers, and decodes.

4. Security Specifications

  • Symmetric Encryption: AES-256 in Galois/Counter Mode (GCM) with a 128-bit authentication tag.
  • Key Derivation: PBKDF2 with HMAC-SHA256 and 65,536 iterations.
  • Randomized Salt & IV: 16-byte cryptographic salt and 12-byte initialization vector generated with java.security.SecureRandom for every encoding session.
  • Integrity Check: CRC32 verification for unencrypted payloads; AES-GCM AEAD authentication tag for encrypted payloads.
  • Encoding Header: 4-byte STEG magic header + version byte + encryption flag.
